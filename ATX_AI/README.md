# ATX_AI (FastAPI backend)

Минимальный бэкенд для чата ИИ-помощника криптокошелька:

- Если вопрос **совпадает** с базой знаний (Q&A) → отдаём готовый ответ.
- Иначе → отправляем вопрос в **LLM** (по умолчанию **Groq**), добавляя RAG-контекст из ближайших Q&A.
- Безопасность: **JWT проверка** + **Rate limiting**.

## Быстрый старт (Windows)

1) Создайте виртуальное окружение и поставьте зависимости:

```powershell
cd d:\server_for_atx\ATX_AI
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

2) Сконфигурируйте переменные окружения:

- Скопируйте `.env.example` → `.env` и заполните.
- Минимум для работы Groq: `GROQ_API_KEY`.
- Провайдер выбирается через `LLM_PROVIDER` (по умолчанию `auto`).
- Для JWT (пример HS256): `JWT_ALG=HS256`, `JWT_SECRET=...`.

3) Запуск:

```powershell
uvicorn app.main:app --host 0.0.0.0 --port 8010
```

Откройте Swagger: `http://localhost:8010/docs`

## API

### POST /v1/chat

Заголовок: `Authorization: Bearer <JWT>`

Тело:

```json
{ "message": "Что такое сид фраза?", "session_id": "optional" }
```

Ответ:

```json
{
  "answer": "...",
  "source": "kb" 
}
```

`source`:
- `kb` — найдено совпадение в базе знаний
- `groq` — сгенерировано Groq
- `gemini` — сгенерировано Gemini

### GET /health

Проверка, что сервис жив.

## База знаний (100 вопросов)

Файл: `data/knowledge_base.json` — список объектов вида:

```json
{ "q": "Вопрос", "a": "Ответ" }
```

Сопоставление по умолчанию:

- **Точное** (после нормализации регистра/пробелов/пунктуации).
- **“Почти совпадение”** включается через `FUZZY_EXACT_THRESHOLD` (рекомендую `95`).

Если “почти совпадение” сработало — ответ будет возвращён как `source="kb"`.

## JWT (как проще всего начать)

JWT — это токен, который ваш основной бэкенд (или auth-сервис) выдаёт пользователю после входа. ATX_AI **не должен** сам логинить пользователей — он просто **проверяет** JWT в заголовке `Authorization: Bearer <token>`.

Самый простой стартовый вариант:

- `JWT_ALG=HS256`
- `JWT_SECRET=<секретная строка>` (одна и та же на сервисе, который **выпускает** токен, и на ATX_AI, который **проверяет**)

Для разработки можно быстро генерировать тестовый токен скриптом:

```powershell
cd d:\server_for_atx\ATX_AI
python tools\mint_jwt.py --secret "your_secret" --sub "user-123"
```

В проде чаще используют `RS256`: тогда у выпускающего сервиса есть **приватный** ключ, а ATX_AI хранит только **публичный** (`JWT_PUBLIC_KEY`).

## Вариант без аккаунтов (MVP)

Если у вас нет логинов/аккаунтов, но хочется минимальную защиту от случайных запросов:

- В `.env` задайте `SHARED_BEARER_TOKEN=<длинная_случайная_строка>`
- Клиент (кошелёк) будет отправлять `Authorization: Bearer <эта_строка>`

Это **не заменяет** нормальную аутентификацию (токен можно извлечь из клиента), но для MVP + rate limiting обычно достаточно.

## Примечания по безопасности

- Сервис **никогда** не должен просить у пользователя сид‑фразу/приватные ключи.
- В системном промпте Gemini есть правило: не запрашивать секреты и не давать инструкций для мошенничества.
- Rate limiting настраивается через `RATE_LIMIT`.

## Groq (рекомендовано)

1) В `.env` задайте:

- `GROQ_API_KEY=...`
- (опционально) `GROQ_MODEL=...`

2) Запросы будут идти через OpenAI-совместимый API Groq.

## Gemini (опционально)

Gemini может быть недоступен в некоторых локациях/странах (гео-ограничения Developer API).
Если используете Gemini:

- `GEMINI_API_KEY=...`
- `LLM_PROVIDER=gemini` (или `auto`, если Groq-ключ не задан)
